3)Commands/Tools used:

*git checkout -b update-about — Created and switched to the `update-about` feature branch.
*git push -u origin update-about — Pushed the new branch to the remote GitHub repository.
*git checkout main / git push origin main — Switched back to `main` and pushed.
*Keynote & GitHub — Opened/inspected the Pull Request.

4)My Understanding:
Staging (`git add`) places selected file modifications into the staging area (index) so you can review and group related edits before saving, 
whereas committing (`git commit`) records all staged changes as a permanent snapshot with a unique hash in the `.git` repository history. 
A branch provides an isolated line of development so changes can be built and tested safely without modifying `main`, and a Pull Request proposes merging those branch changes into `main` after review.
